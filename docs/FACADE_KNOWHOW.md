# 판상·탑상 아파트 입면 작업 노하우 (여러 동을 만들며 틀렸다가 고친 것만)

특정 건물 값은 없다. 건물 하나에만 해당하는 사실은 그 프로젝트 메모에 둔다.

## 1. 순서 (한 면씩 끝낸다)
1. 사진 전부 보기 → 면마다 어느 면인지 정하기(창 패턴이 아니라 옥상 실루엣·동 번호 글자로).
2. 스캔 정사영(20 px/m)으로 덩어리 → zone(같은 마감 구간) → 창 목록 → 특수 요소.
3. **면 하나를 고칠 때마다** `tools/facade/pair_ortho.py` 로 스캔|모델을 같은 축척으로 놓고 눈으로 본다. 보고 전에는 **모든 면**(정면·뒷면·꺾인 동체 각 면)을 한 번씩.
4. 비교는 한 번, 바로 수정·재빌드. 길게 분석만 하다 끝내지 않는다.

## 2. 정사영 비교 (pair_ortho.py)
- 모델 그림의 카메라 yaw = 스캔 view 와 같다. 회전한 동체는 -45 처럼 준다. `--auto-shift` 가 가로 어긋남을 찾는다(회전 동체에서 30 px = 1.5 m 어긋난 적 있음). 상관 0.7 미만이면 다른 면이거나 범위가 틀린 것.
- view 180(뒷면)은 가로 범위가 월드 x 의 부호 반대(월드 x = -a).
- Blender `-b -P` 출력 경로는 항상 절대 경로.
- 열 점유 프로파일 상관으로 "이 모델 뷰 = 저 스캔 뷰" 를 자동으로 고를 수 있다(모든 조합을 돌려 가장 높은 것).

## 3. 창 측정의 함정
- 층 무늬가 4층 묶음(흰 띠가 4층마다)인데 주기 1로 중앙값을 내면 창 위끝이 층 꼭대기(2.85)로 나온다 → 창과 어두운 스팬드럴이 이어져 "연속 유리 기둥"이 된다. **주기 = 무늬 주기**(winlist 의 period 인자), 사진 4배 확대로 창 높이를 눈으로도 확인.
- 창이 위치한 구역 경계(zone a 범위) 5 cm 안이면 조용히 사라진다 → 경계를 창에서 10 cm 이상 띄운다.
- 창 윗단(head)·아랫단(sill)은 하나의 값이 아니다: 구역마다(발코니 열 / 좁은 열 / 작은 창) 다르다. 한 구역의 값을 다른 구역에 복사하지 않는다.
- 창 아래 흰 줄은 리빌 그림자다(막대·선반을 만들지 않는다). 창은 모두 벽 안쪽으로 들인다.
- 루버 / 창 구분: 사진 4배 확대로 가는 가로줄(루버)인지 유리 반사(창)인지 본다. 스캔의 "어두운 직사각형" 만으로 정하지 않는다.
- 미닫이 창(1.0~1.8 m)은 두 짝 + 가운데 멀리언(`facade_engine.SASH = True`).
- 스캔과 VR 사진이 다르면(원근·텍스처 차이) 사진이 우선이지만, 사진은 원근 때문에 가까운 면이 커 보이므로 위치(m)는 스캔 정사영으로 재고 종류·유무는 사진으로 정한다.

## 4. 도색
- 큰 사각형 몇 개 + 층 규칙. 4층 묶음 흰 띠는 `paints` 의 `f=(첫,끝), p=4` 로(레이어 2: 자동 sill 패널과 겹치면 COPLANAR).
- 색은 한 장의 햇빛 사진에서 뽑지 않는다(흰색이 날아감). 같은 면의 흰 틀 대비 비율로.

## 5. 옥상
- 닫힌 벽처럼 보이는 가장자리는 철제 난간일 수 있다 → `ROOF_RAILS[dong] = [(part, axis, c, s, a0, a1, slab)]` + `RAIL_DIM[dong] = (턱 높이, 난간 높이)`. 모든 바깥 가장자리 런은 `heightfield` + `walls_of` 로 만들 수 있다. 모서리에서 레일 끝 면이 기둥 면과 1 cm 안이면 COPLANAR → `RAIL_F = 0.03`.
- 옥상 "장식 틀"(루버 화면)을 비우라는 요구: 기둥(solids) + 보. **보는 `canopies`(7번째 항목 = 재질)로** 닫힌 상자로 만든다. solids 는 bottom 면을 빼서 공중의 보는 LODCHECK 구멍이 된다.
- 낮은 지붕(z<15)에는 파라펫을 두르지 않는다.

## 6. 입구·저층부
- 입구 포치는 벽에 붙은 상자: 옆벽 + 기둥 + 인방 + 지붕판 + 오목한 유리문(zone `wsets` 의 D 종류, 높이 3.6). 위치는 같은 각도 사진 + 스캔 정사영(깊이는 눈 추정 → `estimated`).
- 회전한 동체 위의 solids 는 그 동체 로컬 좌표로 준다.

## 7. 검사
- 보고 전 `cycle.py` PASS + `tools/qa/lod_check.py` PASS. 얇은 수평 부재(보, 레일)는 아래에서 볼 때 구멍이 되기 쉽다.
- COPLANAR 진단: `tools/facade/coplanar_diag.py`(Blender) 로 겹치는 쌍의 위치를 찾는다. 3 mm 차이로 같은 방향 면이 겹치는 경우가 많다(레일 끝 vs 기둥).

## 8. 습관 (실제로 반복한 실수)
- 알고 있는 교훈을 "읽었다" 로 끝내지 말고 도구를 돌릴 때 실제로 적용한다(4층 주기, 확대 확인).
- 첫 면만 맞추고 "고쳤다" 고 보고하지 않는다. 사용자가 "창이 많이 틀렸다" 고 하면 모든 면을 다시 비교한다.
- 메모리 파일은 길이 제한(80줄)을 지키고, 비슷한 항목은 합친다.

## 9. VR 사진과 정확히 비교하기 (가장 확실한 방법)
- meta 카메라(pos·fov·dir)로 스캔을 렌더(`scan_photo_cam.py`)하면 사진과 픽셀 단위로 일치한다. 같은 카메라로 모델을 렌더(`model_photo_cam.py`)해 나란히 보면 어느 창·띠가 틀렸는지 한눈에 보인다. angle 0/180 의 카메라 방향·높이 계산은 LESSONS(프로젝트 memory) 참고: 높이 = pos[1]×100 − 지면, 거리 50 m.
- 사진 속 위치를 벽 위 좌표로 바꿀 때는 핀홀 식으로 벽 평면과 교차시킨다. 깊이가 다른 면(튀어나온 코어, 45° 면)은 정사영 x 와 1 m 넘게 어긋날 수 있다.
- 존이 없는 벽은 엔진이 창을 자동 생성한다(넓은 2짝 창). 보이는 모든 벽을 `walls_of` + `split_zones` 로 열거해 AUTO 가 남지 않게 한다.
