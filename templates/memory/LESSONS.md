# LESSONS.md — 지금까지 배운 일반 규칙 (모든 프로젝트 공통, 짧게 유지)
> 작업 시작 때 읽는다. 건물 한 채에만 해당하는 사실은 여기가 아니라 `projects/<이름>/` 안 메모에 적는다.
> 새 교훈은 "무엇이 틀렸나 → 그래서 이렇게" 한 줄로 추가하고, 비슷한 것은 합쳐 80줄 안으로 유지한다.
> 범위는 `docs/agent/MEMORY.md` 를 따른다. 건축물별 색상·좌표·창 수열·층 규칙은 프로젝트 관찰 파일에만 적는다.

## 규격·내보내기
- FBX 는 `FBX_SCALE_NONE`(CS2 는 FBX 단위를 무시하고 cm 로 읽음). Blender 5.x 는 API 가 달라 cs2kit 이 처리한다. 인게임·FBX 는 이 환경에서 검증 못 함 → 보고에 "게임에서 확인할 것"으로 남긴다.
- 메인 재질 1개, `_Win`/`_Gls` 는 재질 없음, LOD1 < 메인 50%, LOD2 ≤ 500 tris, 이름에 밑줄 금지.

## 사진과 치수
- 층 번호는 특징 층(대피층 등)부터 센다. 매물 표시 층수·손으로 센 번호는 ±1 틀린다. 번호는 항상 그림으로 확인.
- 3D 지도·VR 캡처는 위에서 내려다봐 세로가 눌려 있다 → 벽 크기를 모르고 가정하면 가로 비율이 틀어진다. 아는 폭(세대 폭×세대 수)이나 층 수·층고로 `size_m` 을 먼저 정한다.
- 참고 사진은 형태 파악용. 사진을 텍스처로 쓰거나 출력 폴더로 복사하지 않는다. 사진 속 단지 이름·간판은 쓰지 않는다.
- 사진에서 읽은 값이 TASK.md 와 다르면 TASK.md 가 우선(루버·난간·발코니·창 종류·커튼월).

## 모델링
- 도색은 "큰 사각형 몇 개 + 층 규칙". 칸마다 자동 칠하면 유리·그림자·반사가 섞인 그림이 된다.
- 창은 벽마다 목록(위치·폭·종류), 특징 층만 다르다. 균등 간격 규칙으로 창을 만들지 않는다.
- 단순화하지 않는다: 5 cm 이상 앞뒤로 어긋나는 면은 별도 지오메트리. 타일 비교(`cycle.py --tiles`)로 단순한 곳을 찾는다.
- 커튼월·반사 유리는 사진으로 읽기 어렵다 → 모듈 폭·스팬드럴은 TASK.md 값 또는 확대 사진에서 눈으로 잰 값. 창과 벽이 구분 안 되면 억지로 읽지 않는다.

## 도구 사용 (facade_paint 등)
- 창 인식에 "어두운 세로 띠는 창이 아니다" 같은 자동 제외 규칙을 넣지 않는다(세로 도색 띠 안에도 창이 있을 수 있음 — 사용자 지적). 이상하면 `--window-mode color:#hex` 로 사람이 정한다.
- 실제 사진에서 자동 인식은 층 줄은 잘 맞지만 창·도색은 거칠다. 숫자만 믿지 말고 그림을 눈으로 본다.
- 합성 시험만 통과한 도구는 "실제 사진에서 미검증"이라고 보고한다.

## 환경·파일 다루기
- Windows 셸에서 코드 파일 쓰기는 Claude Code 의 Write/Edit 도구로(here-string·put.py 는 Codex 용).
- 문서를 셸 heredoc 으로 쓸 때는 반드시 인용형(`<<'EOF'`). 인용 안 하면 백틱이 명령으로 실행돼 글이 비어 버린다.
- 업로드된 파일은 CRLF/LF 가 섞여 있을 수 있다. 합칠 때 LF 로 맞춘다.
- 사용자가 요청하지 않은 다음 단계로 넘어가지 않는다. 동작이 바뀌는 수정은 먼저 제안하고 승인받는다.
